# AML Alert Escalation — team_E418F3DF

Предсказание вероятности эскалации сигнала финансового мониторинга (AML alert)
по агрегированной истории транзакций клиента.

## Результат

- Метрика: ROC-AUC на out-of-fold предсказаниях, стратифицированный 5-fold, усреднение по 5 seed.
- **Итоговый AUC: 0.6262** (устойчиво, по отдельным seed 0.616–0.624).
- Практический смысл: если проверять топ-20% сигналов по модели, среди них ловится ~32% всех
  реально эскалированных случаев против 20% при случайном отборе.
- Честное ограничение: `miqdor_indeksi` — нормализованный индекс суммы, не сырая валюта, и в
  данных нет данных о контрагенте операции — это потолок качества без графа связей между счетами.

## Путь к результату

1. Буквальные признаки из ТЗ (25 шт.) → AUC 0.594.
2. Расширенные агрегаты + вес класса (`scale_pos_weight`) → AUC 0.598, но диагностика
   (`best_iteration_` = 3–4 раунда) показала, что вес класса вредит обучению.
3. AML-специфичные признаки (интервалы между транзакциями, layering, всплески активности)
   + отказ от веса класса, регуляризация вместо этого → AUC 0.6205 на одном seed.
4. Усреднение (bagging) по 5 разным random_state → финальный **AUC 0.6262**.

## Файлы

- `notebook/solution.ipynb` — полный пайплайн от загрузки данных до сборки `team_E418F3DF.csv`.
- `features.py` — построение финальных признаков (57 шт.) из сырых транзакций.
- `train_v3.py` — обучение на одном seed, A/B без/с весом класса.
- `train_final.py` — финальная сборка: 5-seed bagging, сохранение submission и OOF-предсказаний.
- `dashboard.py` — Streamlit-дашборд: баланс классов, распределения признаков по классам,
  важность признаков, качество модели.
- `team_E418F3DF.csv` — итоговый submission.
- `feature_importance_v3.csv`, `auc_history.txt` — вспомогательные артефакты для дашборда.

## Как запустить

Данные (`fintech_data`, ~7 млн строк транзакций) в репозиторий не входят — нужно положить их
в `~/Downloads/fintech_data` или поправить путь `D` в начале `features.py` / первой ячейки ноутбука.

```bash
pip install -r requirements.txt
# macOS: LightGBM требует libomp отдельно
brew install libomp
```

Полный пайплайн — открыть `notebook/solution.ipynb` и прогнать все ячейки (Run All),
~5-10 минут на полных данных.

Дашборд (не требует сырых данных, использует уже посчитанные признаки из `train_features_v3.parquet`):

```bash
streamlit run dashboard.py
```

Окружение, на котором проверено: Python 3.9.6, lightgbm 4.6.0.
